# OpenGoLive 研发计划与待办优先级

更新日期：2026-11-03。[English](roadmap.md)

当前重点是让单机、内网和 AI Agent 发布更可靠：先完成修复交付，保证升级、数据恢复及自动化失败处理可验证，再扩展多人协作和基础设施。按下列里程碑顺序推进；没有确认的发布日期。`0.9.8` 是下一版候选号，尚未发布，也不是发布日期承诺。

## 推进顺序与里程碑

| 阶段 | 范围 | 进入条件 | 交付/退出条件 |
| --- | --- | --- | --- |
| M0：修复正式交付 | REL-01 → REL-02 → REL-03 → REL-04 | 当前修复与验收资料可追溯 | 审查、最终 CI、安装/升级验收完成；授权发布后补正式源验收。候选版本 0.9.8，不混入协作/存储新功能 |
| M1：单实例可靠性 | DATA-01 + OPS-01 → AUTO-01；ENV-01/ENV-02/QA-01 按环境准备情况推进 | M0 发布交付完成；建立隔离资源与证据目录 | 恢复演练、Agent 失败路径和环境覆盖矩阵可重复执行；未覆盖项仍明确展示，不将缺少测试环境写成通过 |
| M2：数据量增长 | DATA-02，持续更新 QA-01 | 有数据规模与性能基线，先确认可测量目标 | 大表统计/搜索/分页准确，性能改善有对比数据；保持已有 CLI/页面契约 |
| M3：团队协作 | COLLAB-01，再按需求确认 AUTH-01 | 明确的多编辑者或团队授权需求 | 无静默覆盖、权限规则明确，具备审计和回归证据；版本号另定 |
| 按需阶段 | SCALE-01 / STORE-01 | 分别满足双实例或真实 NAS/WebDAV 触发条件 | 先立设计与验收边界，再排独立版本；不因方向已在路线图就默认开工 |

没有容量和环境承诺前，不填写固定日期或未经估算的工期。每项开发前拆成 issue/PR，写明依赖、验收用例、证据目录及实际覆盖范围；实施完成后更新本表状态。新的优先级调整需说明用户收益及被挤出的工作。

## 本阶段边界

- 单机 Agent 发布、明确诊断、备份恢复与数据准确性优先。共享会话对仅用本机 CLI 或静态 token 的用户收益有限，不引入强制的共享基础设施。
- WebDAV 是页面文件存储适配；不自动提供网页托管、共享登录、组权限、数据库备份或高可用性。
- TLS/Docker 是验证缺口，不自动等同于产品不可用；在补齐前准确说明适用范围，不声称相关路径已验收。
- 已有安全扫描、权限与脱敏约束持续作为发布回归项；不将计划更新解释为合并、发布或部署授权。
