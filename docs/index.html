01 / YOUR INFRASTRUCTURE

Why it exists

You have an HTML file — a report, a dashboard, an internal tool — and you need it on a URL your colleagues can open. The usual answers are a cloud platform that can't touch your data, or a bare nginx that gives you nothing but a file server. html-golive is the middle ground: run it yourself, keep everything inside your network, and still get the conveniences you expect.

Your data stays put

Runs entirely on your own machine or server. No account, no telemetry, no outbound calls by default — works airgapped.

Zero configuration to start

Start with local files and SQLite out of the box. No database service or object store to provision.

Grows with you

Choose SQLite, PostgreSQL, MySQL or Supabase in configuration. Store HTML separately on local files, Supabase Storage or S3-compatible storage.

02 / THE TOOLKIT

What you get

Everything below ships in the box — one install, no plugins to hunt down.

Publish & roll back

Every publish snapshots the previous version. golive rollback returns to any of them instantly.

Edit in the browser

Owners and maintainers get an inline editor on the live page — fix a typo without touching the source file. Saves are scanned and snapshotted.

A database for static pages

A stable window.TemplateAPI provides CRUD. SQLite / PG / MySQL use a server proxy; Supabase uses public keys governed by RLS.

Secrets scanning

Rule-based detection of API keys, tokens and personal data before anything goes live — with optional LLM second-pass review.

19 built-in styles

Turn an unstyled document into something presentable with --style. Fonts come from public CDNs or your own mirror.

Admin console

A light/dark, bilingual workspace at /admin: editable global settings, sites, permissions, data and precise database diagnostics.

Real authentication

Static token for quick setups, or OIDC with one-line presets for Google, Auth0, Okta, Azure AD, Keycloak and Authentik.

Clone any page

golive clone <url> snapshots a public page, inlines its assets and republishes it as your own.

Docker ready

A Dockerfile and a compose file with an optional MinIO profile — from zero to a running server in one command.

04 / FIRST DEPLOY

Quickstart

Three steps, about a minute. No configuration file needed to begin.

Install

Python 3.9+. Use html-golive[mysql] for MySQL or html-golive[postgres] for PostgreSQL.

$ pip install html-golive

Publish a page

Point it at any HTML file. It scans for secrets, applies a style, bundles assets and registers the site.

$ golive publish report.html --style minimal

Serve it

Use an explicit 127.0.0.1 listener for local checks. Saved configuration can change defaults; configure access control before sharing.

$ golive serve --host 127.0.0.1 --port 8787 🚀 http://localhost:8787/ · admin portal: /admin

05 / UNDER THE HOOD

Architecture

Three pluggable interfaces. Start on the left column, move to the right when you outgrow it — your commands and your pages don't change.

Storage

  • local filesystem (default)
  • supabase storage bucket
  • s3 MinIO / COS / OSS / TOS

Registry

  • sqlite single file (default)
  • postgres / mysql server-side DSN
  • supabase PostgREST table

Data

  • sqlite / postgres / mysql server proxy
  • supabase page-direct, GRANT + RLS
  • none optional data-layer disable

Identity

  • none loopback-only access
  • token shared bearer token
  • oidc Google, Okta, Keycloak…
